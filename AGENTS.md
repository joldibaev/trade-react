# trade-react agent instructions

## Project

trade-react is the web client of the Cosmos accounting and ERP system (a small
retail chain in Uzbekistan). It replaces the Angular client `trade-ng` for good.
The server is TradeNet (ASP.NET Core 10, PostgreSQL), a separate repository;
the only contract between them is TradeNet's OpenAPI document. trade4 (NestJS +
Angular) is the previous version: read it only for business and UI
requirements, never copy its design, and treat every requirement as a
hypothesis: list the ones you take and ask the owner about doubtful ones, with
a recommendation.

How the client is built and why: `docs/`. The npm scripts in plain words:
`README.md`.

The owner works on a Mac and on Windows; the sibling repositories (TradeNet,
trade4-old) sit next to this one. Durable knowledge (a decision, a rule, a
fact) goes into this repository: this file, `docs/` or `docs/backlog.md`. An
agent's local memory stays on one machine and is lost on the other.

## Talking to the owner

- The owner (Nurlan) reads Russian and does not write code. Reply in Russian,
  in plain words, with a concrete example for each non-obvious point. Put the
  question or decision first.
- Treat an owner proposal or a rule (this file included) as a hypothesis. If
  it is weaker than an alternative, say why once, with the cost.
- Whenever a library or a browser feature could replace our code, propose it
  unasked, with what goes away and the cost.

## Stack

Vite, React 19, TypeScript (strict), TanStack Router (file routes in
`src/routes`), TanStack Query (all server data), TanStack Table + Virtual
(through `DataTable` only), TanStack Form (through `useAppForm` only),
shadcn/ui on Base UI with Tailwind 4 (preset `b1VlIttI`), `openapi-fetch` with
types from `openapi-typescript`, Vitest + Testing Library, Playwright.
Not used, on purpose: Redux/Zustand (server data lives in Query, the rest in
the URL or a component), Next.js, a second styling system next to Tailwind,
an i18n library. Reasons and rejected options: `docs/decisions/0001-stack.md`.

## Rules

### The contract with TradeNet

- Types and paths come from `src/api/schema.d.ts`, generated by `npm run api`
  from the running API. Never edit it by hand; commit it, so a build needs no
  running API. After a TradeNet change, regenerate and fix what no longer
  compiles.
- Every call goes through `api` + `unwrap` (`src/api/client.ts`); `fetch` is
  banned elsewhere by lint. A failure is an `ApiError` with a `code`.
- Errors are shown by `code`, never by `title` (TradeNet ADR-0004): every
  `ProblemCode` and `FieldCode` has a text in each catalog, typed
  `Record<code, string>`, so a new server code fails `npm run typecheck`
  after `npm run api` until it is translated. Show a failed request with
  `ProblemAlert` next to what it broke; it also shows the support id
  (`traceId`).
- Money, quantities, unit prices and rates are exact decimal strings
  (`"12500.00"`) and never become JS numbers: lint bans `Number()`,
  `parseFloat`, `parseInt` and unary `+`. Display with `formatDecimal`
  (`src/lib/decimal.ts`); send back exactly what the API's scale allows.
  Totals come from the server.
- A 401 from any request (except sign-in and `/me`) means the session ended:
  `main.tsx` forgets the person once and the signed-in layout sends them to
  sign-in with the page as the way back. Do not handle 401 per screen.
- Writes are never retried automatically (`mutations.retry: false`). TradeNet
  has no `Idempotency-Key` today; when sales or payments bring it back, such a
  write gets a UUIDv7 per operation, reused for every attempt of it.
- An edit sends the `version` it read; a 409 `VERSION_CONFLICT` keeps the
  person's edits on screen and lets them choose.
- The dev proxy (`vite.config.ts`) keeps the browser's `Host` (no
  `changeOrigin`), or TradeNet's CSRF check refuses every write.

### Code layout and one implementation per thing

- `src/routes/` — thin route files: search-param validation, guards, and one
  page component. `src/features/<feature>/` — the screens, queries and forms
  of a feature. `src/components/` — shared app components.
  `src/components/ui/` — shadcn sources, added by `npx shadcn add` (the CLI pinned in `package.json`).
  `src/api/`, `src/i18n/`, `src/lib/` — shared mechanisms.
- Every list is `DataTable` (`src/components/data-table`): virtual rows in a
  native `<table>`. A growing list comes through `useCursorSource` over
  `cursorListOptions` (`src/api/cursor-pages.ts`, infinite scroll over
  `nextCursor`); a short list TradeNet answers whole (stores, groups,
  sessions: one page, `nextCursor` null) through `wholeListOptions` and
  `useArraySource`. Every TradeNet list is `{items, nextCursor}`. Lint bans
  `@tanstack/react-virtual` outside it. A new list behavior goes into
  `DataTable` for every list, not into a page.
- Every form is `useAppForm` (`src/components/form`). A new kind of field
  (decimal, select, date) is added there once. Field errors are field codes,
  from client validators and from the server alike; `showServerFieldErrors`
  puts a `VALIDATION_ERROR` under its fields. A check over the whole form (a
  price grid, a barcode naming a removed package) goes through
  `useFormChecks` (`src/components/form/form-checks.tsx`), never through
  TanStack Form's field meta, which loses it, nor through a field validator,
  which a scrolled-away virtual row does not run. Create and edit forms are a
  `FormDialog` with `useRefusal`; an edit sends only the changed fields
  (`changedFields`) with its `version`.
- Permissions: `useCan()` hides menu items and buttons; a route that needs one
  calls `requirePermission` in `beforeLoad` (or sits under `_app/_admin`), so
  a typed address shows "no access", not a failed request.
- List filters live in the URL (`validateSearch`), so Back and a shared link
  restore them.
- shadcn components may be edited, but stay close to upstream so updates stay
  plain diffs. They carry no app texts: a label comes in as a prop (see
  `SidebarTrigger label`, `SheetContent closeLabel`).
- No application hotkeys and no shortcut labels (owner decision in trade4,
  2026-10-03): the Ctrl+B of the shadcn sidebar and the D of the theme
  provider were removed. Standard keys of controls stay.
- Keep components small. Comments say why, not what; code and comments are in
  English.

### Languages

- Russian (`ru`, the source catalog), Uzbek in Latin script (`uz`, tag
  `uz-Latn`), Kazakh (`kk`). Catalogs are TypeScript objects in
  `src/i18n/messages`; `useT()` returns the current one. A key missing or extra
  in any language fails the typecheck; an empty text fails a test.
- Every visible text, `aria-label`, `title`, `placeholder` and `alt` comes from
  the catalog: lint bans letters in JSX text and those attributes. Product
  names and other user data are never translated.
- A new or changed text is written in all three catalogs in the same change.
  The Uzbek and Kazakh texts so far were written by an agent: tell the owner
  when you add new ones, so a native speaker can check them.
- Numbers use the no-break-space thousands and the decimal comma of all three
  languages (`formatDecimal`), not `Intl`, whose Uzbek and Kazakh data not
  every browser ships.

### Screens

- Responsive from the first commit: width-based (Tailwind breakpoints,
  container queries), never a device check. Every browser check runs on a
  desktop and on a phone viewport.
- Accessibility target WCAG 2.2 AA: native elements first, a label for every
  control, visible focus, errors linked to fields, focus moves to the first
  invalid field after a refused submit, no information by color alone.
- A list page fills the screen; its table scrolls, not the page (a browser
  check guards this).
- Loading, empty and error states are part of every screen: `DataTable` has
  them; elsewhere use `Skeleton`, `Empty` and `ProblemAlert`.

## Rules live in checks

A rule a compiler, lint rule or test can check lives there, not here. When
agents repeat a mistake a check could catch, add the check in the same change.

- `tsconfig.app.json`: strict, `noUncheckedIndexedAccess`.
- `eslint.config.js`: typescript-eslint `strictTypeChecked`, react-hooks,
  jsx-a11y `strict`, and the project rules above (texts, numbers, `fetch`,
  virtual lists). Each message says what to do instead.
- Vitest (`src/**/*.test.ts(x)`): logic, catalogs, components in jsdom.
- Playwright (`e2e/`): what needs a real browser (scrolling 10,000 rows, the
  layout, sign-in), with the API mocked per test, on desktop and phone.

`npm run check` runs all of them; run it before saying work is done, and never
call an unrun check green.

## Git

The remote is GitHub, `origin` (`git@github.com:joldibaev/trade-react.git`);
the main branch is `master`. An agent commits and pushes only to the review
branch the owner names; nothing reaches `master` without his permission.

One commit per self-contained change, Conventional Commits
(`feat(products): ...`), each passing typecheck and lint. History shows final
states: until a review branch is merged, a correction is folded into the
commit it corrects and the branch is pushed again with `--force-with-lease`;
once merged into `master`, history is never rewritten.
